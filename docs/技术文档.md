# 企业智能售后服务 Agent｜技术摘要

版本：对应需求 v1.8　基线：2026-10-19　状态：待重新开发

本文件给出架构摘要与导航。实现级Schema、事务、队列、路由、数据库表和验收细节以[技术详细规格](技术详细规格.md)为准；业务范围、业务规则和验收口径以[需求详细规格](需求详细规格.md)为准。摘要不得覆盖详细规格；经批准的技术变更先更新技术详细规格，再同步本摘要并记录版本。

## 系统边界

本地以隔离进程模拟商品主数据、OMS订单、售后、WMS仓储与支付渠道；各系统拥有自己的ID、状态、schema和事务。生产以适配器连接企业系统，不能假设跨库原子事务。Outbox/Inbox、稳定操作ID、幂等、回调和对账负责恢复跨系统流程。

Agent API、MCP、Worker按现有目标分进程。Agent通过受控工具访问业务能力；Gateway签发可信AuthContext，MCP重复授权。支付执行、仓储收验货写操作只允许服务身份/获授权员工用例，不注册为模型工具。

## 本体与图谱

正式本体使用RDF/OWL 2（类、属性、关系和个体语义），SHACL检查数据形状，版本化JSON管理外部系统映射及指标。Neo4j既有 `Product` 节点映射为本体 `CanonicalProduct` 类的实例；两种名称在OWL中显式等价，不复制产品实体。稳定知识边和售后交易边使用各自查询白名单；动态订单、支付、退货和退款记录由权威系统保存，分析用带版本的只读投影连接。

OWL/SHACL帮助统一跨系统语义与校验结构；金额上限、身份、确认、验收、幂等和支付状态仍由服务端业务规则执行。

## 售后状态与恢复

审核、实物退货、资金状态独立。需退货的申请先获批、再WMS验收，随后由支付协调器校验客户确认、金额、币种、原支付、权限与预留并提交原路退款。权威支付成功才写账并结转预留；未知状态查询原执行ID，不能当失败重付。外部写入无幂等/查询能力则转人工核对。

跨服务请求透传 `trace_id`、`correlation_id`；异步事件带 `operation_id`、`causation_id` 和父事件引用。调查可沿订单/退货/支付源记录或trace/span、Outbox/Inbox及重试链路定位首个失败点。日志脱敏并记录采样/证据覆盖，逐条下钻重新授权。

## 指标与异常调查

指标公式、批次、窗口、样本门槛版本化；先按事实粒度去重聚合再关联，返回分子分母、源水位、快照、映射与对账版本。数据不完整时标记partial/blocked，不作完整排名。

异常调查覆盖业务指标突变、系统间状态/金额不一致、接口错误/超时、队列积压和知识索引故障。先跑数据质量门，再沿授权维度与系统因果链下钻。调查留不可覆盖的快照、条件、证据引用、结论修订和访问审计。模型只转述有证据的候选因素；统计相关性不等于因果结论。

## 分层、验证与交付

采用Interface / Application / Domain / Infrastructure四层与依赖倒置；通过Port/Adapter隔离Neo4j、MySQL、消息队列、WMS、支付及检索实现。详细目录见[项目目录结构](项目目录结构.md)。

关键验收包括：OWL/SHACL与映射一致性、跨租户隔离、分批收货验收、支付幂等/超时/回调/对账、退款率精确分子分母、异常快照重放和证据权限。标准ID贯通、事件因果链及异常定位须作为集成验收项。

项目当前只保留docs与data，无依赖配置、启动入口或业务代码。先以独立模拟系统完成契约与跨进程验收；具体生产API、阈值、原因分类和遥测保留策略在接入前由各责任方确认。详见[技术详细规格](技术详细规格.md)。
