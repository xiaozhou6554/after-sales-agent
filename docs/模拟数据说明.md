# 模拟数据说明

> 数据只用于隔离开发与自动化验证，全部为虚构事实。数据范围、字段和验收期望以本文、[需求详细规格](需求详细规格.md)及机器可读 Schema 为准；生成文件不能证明应用已实现。

## 数据版本

旧 v1 模拟数据已弃用。v2固定种子生成149条场景记录，覆盖需求详细规格中的全部131个TC（含边界变体）；此前缺失的61个TC已补入需求原文测试输入和验收标准。新增内容仍是设计夹具，验收标准尚未转换为应用运行断言。v2同时在`systems.json`中生成1,000笔跨系统合成订单，覆盖2个租户、10个规范商品、OMS订单及明细、PIM/OMS/WMS商品编码映射、签收、支付、退货收货/质检、退款和产品级指标快照；订单带团队、渠道和区域维度，可用于排名、过滤和原因贡献分析。所有关联事实均为虚构，不连接真实系统。当前业务数组共7,094条记录，逐类数量见manifest。知识样本包含10篇带租户、版本、有效期和状态的合成文档及7条有证据的图谱边。`acceptance-test-map.csv`为131个TC列出场景和计划测试文件，所有运行测试仍标为`not_implemented`。场景数量和数据量都不等同于Agent运行验收通过数。

v2场景按需求TC映射，不以“场景条数”冒充通过的验收用例。每条场景须有身份与租户、输入、隔离前置事实、结构化`expected`、TC和FR映射。`expected`依照 [`expected-v2.schema.json`](../data/scenarios/expected-v2.schema.json)，涵盖业务事实、逐TC验收标准、允许/必须/禁止的工具调用、副作用、证据、禁止行为和审核/退货/资金状态。校验器验证全部需求TC均有场景，并检查补齐场景的输入与验收标准逐字对应需求表。应用执行器未实现前，测试结果只能标为`not_executed`，不能宣称业务验收通过。

## 跨系统事实与权威来源

模拟资产至少包含租户与操作者、统一商品标识及来源系统映射、订单及明细、签收批次、退货授权、WMS实收与质检、支付原始交易、退款执行与回调、对账结果、指标投影快照、异常调查及运行追踪证据。订单归OMS，商品编码归PIM，收货和验收归WMS，资金结果归支付渠道；映射及指标规则带版本。场景引用必须满足同租户、订单/商品/明细归属、支付与退款金额守恒、授权与验收状态一致等约束。

本体定义跨系统概念和映射关系；知识图谱承载有证据、版本和有效期的稳定商品/政策关系。动态订单、收货、退款事实仍以各自权威系统为准，分析通过只读投影关联。本体或图谱不得覆盖源系统事实。

## 分析与异常调查数据

产品退货率和退款率场景保存指标版本、观察窗口、批次、分子、分母、样本门槛、来源水位和投影快照。商品汇总先按业务粒度去重，再汇总分子分母计算比率；不能平均各子组百分比。数据不足、源水位落后、映射歧义、对账差异或窗口未成熟时必须输出质量问题或不可比较，不得把缺失当零或编造根因。当前窗口和最低样本数仅为模拟参数，须由业务/财务批准后才能用于生产。

异常调查用例覆盖业务指标异常、跨系统状态/金额冲突、数据质量门失败、外部接口故障、消息积压/死信、知识索引失败及遥测缺失。每个调查预期应能由固定快照、源记录引用、trace/event/operation ID及修订号重放；证据不足时明确标为未知，不把相关因素说成已证实因果。

## 生成和校验

步骤16的`data/manifests/knowledge-v2.json`锁定10篇知识文档、7条图谱关系和7条公开标注样例。对既有`corpus.json`和生成定义只增量补充FAQ与技术规格A.2规定的关系类型、端点、版本和有效期；未重建业务事实或移动本体原文。开放有效期在发布候选关系中明确记为`9999-12-31`，来源证据仍保留`valid_to: null`。步骤22新增的`data/mock/v2/logistics.json`含2条明确运单事实，时间与`systems.json`签收批次核对；只读物流适配器读取该文件，不把OMS签收记录临时拼成物流轨迹。两份新清单的校验命令见`data/README.md`。2条物流轨迹不足以代表完整物流业务覆盖，长时间停滞只在确定性规则单元测试中验证，运行场景验收仍待补齐。

在项目根目录运行：

```powershell
node data/scripts/generate_mock_data.cjs
node data/scripts/validate_mock_data.cjs
```

生成器和校验器不得调用外部系统。机器接口合同见[`data/contracts/`](../data/contracts/)；OpenAPI、MCP工具manifest、事件信封、事件目录和DDL与本文契约共同版本化。校验报告写入`data/generated/reports/`，检查manifest哈希、Schema、租户隔离、跨系统归属、金额守恒、TC/FR覆盖和证据引用。公开holdout仅作为固定回归集，不是盲测；真正独立评测需在实现阶段由未参与开发者保管。

## 保留集

保留场景须按业务模板族或规则变体隔离，不能只更换租户ID或订单号。数据公开可读，因此它不是独立盲测集。测试报告应记录数据版本、生成器版本、Schema版本及每条未执行/不支持的断言。
