# 生产权威系统接入清单

日期：2026-10-21

## 当前结论

本项目目前有完整的业务用例、MCP 工具契约和本地 Mock/模拟实现。当前工作区未提供企业 OMS/PIM、支付渠道、WMS、身份提供方或通知平台的正式 API 契约、沙箱地址、测试租户或凭据注入说明，因此不能安全地编写可运行的生产连接器，也不能用自造接口模拟“接入完成”。生产权威系统接入仍为未验证。

接入边界沿用 Clean Architecture：Domain 与业务规则保持不变；Application 通过端口表达能力；Infrastructure 实现具体系统适配器；bootstrap 按环境选择适配器。不得让 Domain 依赖 Infrastructure，也不得让 Application 导入具体 SDK/适配器。

## 系统接入矩阵

| 系统 | 当前本地实现 | 必须以其为准的业务事实/操作 | 编写生产适配器前需要的权威资料 |
| --- | --- | --- | --- |
| OMS / 订单 | `MockOrderAdapter`、`MySqlMockAddressChangeAdapter` | 订单归属与状态、履约/发货锁定、订单版本、受控收货地址变更及结果查询 | OpenAPI/SOAP 契约和版本；订单/地址变更读写路径；租户与客户标识映射；可改状态与版本/ETag 规则；幂等键；冲突码；地址敏感字段传输/加密规则；沙箱订单及测试租户 |

## 每个连接器统一需要的技术约束

1. 受支持的 API 版本、base URL、调用方身份和证书/密钥管理方式；仅提供凭据的环境变量或密钥库引用名，不在文档、命令行参数或日志中提供密钥值。
2. 请求/响应 schema、枚举映射、金额与时间约定、租户隔离字段、数据分类及可记录字段。
3. connect/read/总超时、限流、重试分类、断路恢复、幂等键格式与保留期，以及“请求已提交但响应丢失”的状态查询方法。
4. webhook/event 的签名算法、时钟容差、去重键、版本兼容、重放防护、死信处理和重放审批人。
5. 可自动重建的 sandbox、合成账号/订单/RMA/退款/地址与预期结果；支付测试必须明确不会转入真实资金渠道。
6. 外部系统负责人与变更窗口、数据保留期限、生产灰度/回滚步骤、监控和告警阈值。

## 接入与验收顺序

1. 接收并核对上述契约，明确每类事实的唯一权威源和冲突处理方式。
2. 只在 Infrastructure 新增厂商客户端和适配器，并在 bootstrap 按 `APP_ENV` 显式装配；生产配置缺失时 fail closed，不回退到 Mock。
3. 为每个适配器增加契约测试、脱敏测试、隔离测试、超时/限流/重试/幂等/未知结果恢复测试；只使用官方 sandbox。
4. 运行相应领域回归、架构依赖扫描、Ruff 和契约验收，再做跨系统演练和经批准的灰度验证。
5. 在真实测试环境中提供调用审计、外部回执和对账证据后，才将该系统状态从“未接入”改为“已验证”。

## 当前待交付输入

开始生产连接器实施时，按系统提供：①官方 OpenAPI/SOAP/事件文档或仓库路径；②sandbox 地址、证书/认证类型及凭据注入名；③合成测试数据和无真实资金/消息副作用的保证；④租户/客户/员工/仓库映射；⑤幂等、重试、回调及对账规则；⑥接口负责人和变更策略。未收到这些资料前，保持本清单与本地 Mock，不新增猜测性的生产端点。
